2️⃣ 슬롯 상세 (쿠버네티스)

  • 사업 상황 신한은행 컨테이너 모니터링 RFP 8월, 늦어도 9월 초 공고. 10월 구축. 엑셈, 와탭, 엔키아 경쟁. 기술점수와 가격점수 평가, 비율 미정. 신한은행 내부 쿠버네티스 환경 증가 추세. 뒤에 붙는 사업 많아 우선 수주가 중요하다는 판단
  • 제약 1차 의견이 세 제품 간 변별력 부족. 기능 나열형 자료는 효과 없음
  • 주제안 컨테이너 지표만 보는 도구와 트랜잭션, DB까지 내려가는 도구의 차이. 컨테이너 지표는 어디나 제공. 컨테이너에서 시작해 트랜잭션과 DB 쿼리까지 한 번에 내려가는 구성이 엑셈원 차별점
  • 근거 자료 클릭업 DSP-42846(KB라이프 Workload Overview), DSP-44090(컨테이너 상세 리소스 관계도), DSP-44088(Network Service 프록시 유형별 지표). 셋 다 관계 표현 요구. 통합개발본부 KB라이프 K8s 고도화 항목에 virtual service 표현과 리포트 개선 포함

  • 형태와 시점 제안서 첨부 2장. 1장은 컨테이너에서 DB까지 내려가는 화면 순서, 1장은 평가표 대응용 기능 대조. 공고 전 완료 필요하므로 8월 셋째 주 목표

신규 제안 상세 (exemONE SingleStore)

  • 확보 자료 회의 첨부 zip 안의 exemONE SingleStore 제품 문서. 문제 정의 4가지와 CORE 8 진단 체계, 영역별 수집 주기까지 정리된 상태
  • 문제 정의 4가지 (그대로 목차 사용 가능)
    1. 노드는 정상, 서비스는 지연. Leaf 8대 CPU 정상, 원인은 파티션 편중
    2. 어느 구간에서 느려졌는지 SQL 하나 안에서 구분 불가
    3. 복제 지연은 장애 발생 전까지 어떤 상태값에도 미노출
    4. 같은 역할인데 설정 상이 시 노드 개별 조회 필요
  • 문서 결론 네 가지 모두 개별 Node 지표가 아니라 Cluster 구조에서 발생하는 문제. 이 문장이 메시지 축
  • 경쟁사 현황 와탭 이미 SingleStore 문서 보유. 겹치는 주제 작성 시 검색에서 밀림
    • docs.whatap.io/singlestore/monitoring-intro 인스턴스, 멀티 인스턴스, 스토리지 엔진, 파티션, 파이프라인, DB 크기, Top SQL, 세션 이력, Lock Tree
    • whatap.io/ko/products/database/ 지원 DB 15종에 SingleStore 포함
    • whatap.io/en/pricing 과금은 Leaf Node 기준
    • 와탭 강조점은 설치 편의. 애그리게이터에만 에이전트 설치 시 리프 자동 발견
  • 겹치지 않는 항목 복제 동기화를 Log Position 차이로 수치화, USD와 Object Storage를 LSN으로 지연 정량 추적과 Blob Cache 적중률, 전 노드 파라미터 중 차이 항목만 Diff 조회, 라이선스 Capacity 노드별과 클러스터 합계, 테이블 단위 Shard와 Primary, Sort Key 지정 여부
  • 제목안 Leaf 노드 CPU가 다 정상인데 왜 느린가
  • 형태 기술 블로그 2편. 1편은 문제 4가지, 2편은 복제와 설정 편차. 제품 페이지에 SingleStore 항목 신설. 7월 SingleStore AI NOW 부스 참가 후속으로 연결
  • 확인 필요 제품 문서의 대외 배포 가능 여부, 화면 캡처 사용 가능 여부

2. 이슈사항 두 건

고객 자체 개발 시작 (현대해상)

  • IT자회사 현대HDS가 AI 활용 자체 DB 성능 모니터링 툴 개발 중. 계속 고도화
  • CIO가 기간계 DB 서버 적용 지시. 이광목 과장이 안정성과 운영 리스크 설명해 현재 방어 상태
  • 영업본부 자료 원문: "향후 AI 기술을 활용해 모니터링 솔루션을 자체 개발하려는 고객사가 점차 증가할 것으로 예상됨"
  • 재료 위치 스프레드시트 기술개발 시트의 맥스게이지 고객 대응 요약. 원인 규명에 공수가 크게 든 사례가 실명으로 정리됨. 폭스바겐 수집 누락은 한 달치 로그 분석 끝에 수집 서버 프로세스 메모리 한계로 판명. 대법원 AIX Tibero 7은 패키지에 표준 OpenSSL 심볼 부재로 데몬 미기동. 케이카캐피탈 RTS 경고는 가드 로그로 확인 후 제거. 하나은행과 KB증권 동일 증상 동시 보고
  • 주제안 직접 만들면 처음엔 되는데 어디서 막히는가. 근거 3축. 장애 원인이 제품 밖에 있을 때(수집 서버 메모리, OS 라이브러리) 규명 공수. 우리 통제 밖 변수(DB 벤더 패키지 정합)가 기동 자체를 막는 상황. 이기종 DB 지원 범위(MaxBot이 Tibero, DB2, Altibase 추가, 9월 SQL Server와 Postgres)
  • 물어볼 사람 이광목 과장. CIO 지시를 막은 논리가 그대로 우리 논리. 사례 인용 범위는 제품기술연구그룹
  • 주의 현대해상 건 자체는 언급 금지. 방어 중 상황이라 외부 노출 시 고객사 내부 문제로 번짐

3. 제품 명칭과 설명 방식

  • 회의에 AXIS, ExTuner, ExpertSQL, AIM, Ask MaxGauge 동시 등장. 정리 안 된 것처럼 보이나 내부 계층은 이미 확정, 담당자도 실명 지정
차세대 MaxGauge
 ├ 제품 기능: 멀티테넌트와 RAC / EXADATA / ExpertSQL
 └ AIM (AI In MaxGauge)  = AI 기능 묶음 이름
    ├ RCA                (장기협 그룹장)
    ├ X-TUNER 연계        (유정오 팀장, 이동기 과장)
    ├ Ask MaxGauge        (김형웅 팀장)
    ├ 통계기반 이상탐지    (김민수 과장, 남병민 과장)
    ├ MaxGauge In Chrome  (이충건 과장, 김재덕 과장)
    └ AXIS 엔진 제품화     (박준연 본부장, 김병오 과장)

exemONE DPM  = 별도 축. 본부 최다 인원 투입
  • 우리 몫 이름 새로 짓기 아님. AIM이 묶음 이름이고 AXIS가 그 안의 엔진이라는 관계를 고객이 알아듣게 쓰는 일. ExTuner는 별도 제품이므로 선 긋기 필요
  • 확보 자료 AXIS 임원회의 발표용 8장(문구, 다섯 단계, 수치), AXIS 본부원 공유용 1만 7천 자(개발 과정과 한계). 둘 다 회의 첨부 zip 내
  • 쓸 수 있는 문구 "SQL 튜닝 판단을 반복 가능한 시스템으로" / "느린 SQL을 보고 최선의 조치만 남기는 엔진" / "개인의 감각에서 증거로 반복되는 조직의 튜닝 절차로" / "좋아 보이는 SQL이 아니라 DB에서 이긴 후보만 보존"
  • 다섯 단계 입력 이해, 병목 우선순위, 대안 경쟁, DB 실측, 재진단. 제품 페이지 구성 순서로 사용
  • 본부원 공유용 활용은 확인 후 LLM과 SFT 접근이 닫힌 이유, 룰 엔진 초기의 모듈별 해석 불일치 문제가 상세 기재. 기술 블로그 소재로는 깊이 있으나 경쟁사 힌트 가능성. 박준연 이사님 판단 선행
  • (고평석 대표) "엑셈 DB 엔지니어들이 축적한 암묵지가 들어가 있음. 이를 AI화, 솔루션화한 기술로 전달할 수 있도록 제품 명칭과 설명 방식도 함께 고민할 필요"
4. 나머지 소재
  • 한국예탁결제원 고객평 "직책자분들 그리고 업무담당자들 모두 인터맥스 화면만 봅니다. 거래가 모두 연결되어 있어 좋아합니다." 인터맥스 전년 대비 28.3% 감소, 삼성생명 PoC 잠정 중단 상황에서 제품 가치를 고객 말로 제시 가능. 회사명 노출과 인용 범위 확인 필요
  • 삼성생명 인터맥스 E2E 제니퍼 윈백 건. 인터맥스와 와탭 경쟁. 1년 사이트 라이선스 1억 9,000만 원. PoC에서 E2E 연결 표현이 관건. 삼성SDS FEP AnyFrame 구간만 진행 예상, SAP Java 부문은 담당자가 시스템 변경 부담. PoC 재개 시점에 E2E 설명 자료 필요
  • MaxBot v1.4 (8/13) 지원 DB에 Tibero, DB2, Altibase 추가. 9월 SQL Server와 Postgres 예정. 이미지 기반 질의 추가. InterMax 5.3과 5.4 소스코드 기반 답변으로 화면부터 API, 데이터까지 연결 관계 확인
  • PWI 웨비나 김민서 과장 준비 착수. 세션 1 PostgreSQL Wait Event와 진단 도구, 세션 2 Memory Lock, 세션 3 HWLock. 진행 중 PostgreSQL 백서와 주제 동일. 묶어서 신청과 다운로드 상호 유입 구성 가능. 백서 오픈 목표는 9월 3주 또는 10월 3주
  • EXPU 브로셔와 로고 디자인 협의 진행 중. 같은 기간 GPU 대시보드와 NPU UI 변경 중이라 브로셔 화면 확정 시점 조율 필요. 물어볼 사람 박용우 이사님
  • 한전 폐쇄망 LLM 구축 7월 27일부터 8월 4일 사이 폐쇄망 풀스택 구축 거의 완료. GPU 드라이버와 도커, vLLM 환경 구성, gpt-oss-120b 서빙, eXemble 구축, VectorDB와 GIS DB 배포
  • 사내 세미나 주제 통합기술본부 7월 신규입사자 세미나가 엑셈원 SaaS화 인프라 아키텍처와 LLM 옵저버빌리티. 기술 블로그 저자 발굴 접점

5. 표현 주의
